1. Summary

Dealership staff need every document about a vehicle in one place. Today those documents are split between the Sales system and the Service system, so finding them means searching twice. The Unified Document Viewer takes a VIN and returns one list of documents from both systems, each labelled with where it came from.

2. Users and their goal

  • Users: dealership staff such as service advisors, salespeople and back-office administrators (A-01).
  • Goal: answer "what paperwork exists for this vehicle?" in a single search, without knowing which system holds what.

3. Goals and non-goals

Goals

  • One search across both systems.
  • One consolidated list, with the source of every document always visible.
  • Useful results even when one system is slow or down.

Non-goals

  • Uploading, editing or deleting documents.
  • Searching/filtering by anything other than VIN (plate, customer name, order number).
  • Previewing document contents inside the viewer.
  • Sign-in and permissions (A-08).

4. Requirements

R2Data aggregationOne search covers the Sales and the Service system at the same time. The user never searches each system separately.

5. Clarifications and assumptions

Decisions that fill the gaps the scenario leaves open.

IDTopicAssumption
A-01UsersDealership staff (service, sales, back office), not customers.
A-02VIN17 letters and digits, no I/O/Q; spaces and case normalised. Check digit not enforced (only mandatory in North America). Example: 1M8GDM9AXKP042788, also accepted as 1m8gdm9axkp042788. It is the hypothetical VIN from Wikipedia's check-digit example, not a real vehicle.
A-03DocumentTitle, type, date, source system and a link, plus a short summary when the source provides one. Clicking a document opens its file from the source system; the viewer doesn't display contents itself.
A-04ListOne merged list, newest first, loaded a page at a time (up to 20; "load more" until it ends; no total count). A file held by both systems appears once per system, each labelled (no de-duplication yet; planned).
A-05A system failsShow the other system's results and name the failed one. If the failure is temporary, its documents come on later pages once it answers again, possibly out of date order. If it is permanent (the system rejects the request), the list continues and ends without it, and says so. When no system answers a page, show an error and let the user retry.
A-06No results"No documents found", not an error.
A-07SpeedResults within 3s; a slower system counts as failed.
A-08AccessSign-in, permissions and dealership filtering are out of scope.

Example document types: purchase agreements, sales invoices, finance contracts and registrations from Sales; repair orders, service invoices, inspection reports and recall notices from Service.

6. Acceptance criteria

  • AC-01: Given a valid VIN with documents in both systems, when the user searches, then one list contains documents from both, newest first, each showing its source system.
  • AC-02: Given a VIN typed in lowercase or with surrounding spaces, when the user searches, then it is treated as the normalised VIN.
  • AC-03: Given input that is not a valid VIN, when the user searches, then a message explains why and neither system is queried.
  • AC-04: Given one system fails or exceeds the time limit, when the user searches, then the other system's results are shown with a notice naming the failed system.
  • AC-05: Given more documents than one page holds, when the user loads more, then the list continues newest first with no document skipped or repeated.
  • AC-06: Given both systems fail, when the user searches, then an error explains both systems are unavailable.
  • AC-07: Given a valid VIN with no documents in either system, when the user searches, then a "no documents found" message is shown.
  • AC-08: Given any search, results or a clear failure appear within 3 seconds.
  • AC-09: Given a document whose source system provides a summary, when it appears in the list, then the summary is shown with its title; documents without one show the title only.
  • AC-10: Given a document in the list, when the user opens it, then its file opens from the source system's link.
  • AC-11: Given the same file in both systems, when the user searches, then it appears once for each system, each labelled with its source.
  • AC-12: Given one system rejects the request permanently, when the user pages through the list, then the list continues and ends without it, with a notice that its documents are missing.

7. Open questions

  • Should users be able to filter by source system or document type? Not required; the demo UI filters client-side, and a server-side filter is a later enhancement.
